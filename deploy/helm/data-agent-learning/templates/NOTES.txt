This release deploys the OFFLINE plane only. The agent runtime, the agent UI and
the neo4j hydrator come from the sibling `data-agent` chart, and this plane reads
that release's data: the sweeper scans ITS Couchbase session bucket, and the
promotion scheduler replays against the warehouse as the SAME tenant. Confirm
COUCHBASE_*, NEO4J_*, EMBEDDING_*, MCP_URL and TENANT_* match the data-agent
release — a mismatch produces no error, only a loop that learns from nothing or
verifies against somebody else's rows.

The external backing services (ClickHouse, MCP, token IdP, OpenAI, Couchbase,
Neo4j, embedding API) are NOT deployed by this chart.
{{- if .Values.redis.enabled }}

Redis IS deployed by this chart — the learning job stream is this plane's private
transport. LEARNING_REDIS_URL is derived for you:

  {{ include "data-agent-learning.redisUrl" . }}

It is UNAUTHENTICATED and ClusterIP: anything that can reach that Service can
read or drain the stream. Restrict it with a NetworkPolicy on a shared cluster.
{{- if not .Values.redis.persistence.enabled }}
Storage is an emptyDir — a restart loses in-flight (PEL) jobs and the DEAD-LETTER
stream. Pending work returns on its own (the sweeper re-enqueues idle sessions);
the triage record does not. Set redis.persistence.enabled=true to keep it.
{{- end }}

To use an EXTERNAL Redis instead: set redis.enabled=false AND
config.LEARNING_REDIS_URL to its URL.
{{- else }}

Redis is NOT deployed by this release (redis.enabled=false). The workloads are
using LEARNING_REDIS_URL={{ include "data-agent-learning.redisUrl" . }}
{{- if not .Values.config.LEARNING_REDIS_URL }}

WARNING: that URL is the chart's last-resort FALLBACK, not something you
configured. Set config.LEARNING_REDIS_URL to your external Redis, or re-enable
redis.enabled — otherwise the sweeper and consumer will fail to connect.
{{- end }}
{{- end }}

This chart renders NO Secret. Every workload mounts
`{{ include "data-agent-learning.secretName" . }}` via envFrom; create it out-of-band
(vault / external-secrets / sealed-secrets) with COUCHBASE_PASSWORD,
NEO4J_PASSWORD, TOKEN_ISSUER_API_KEY, EMBEDDING_API_KEY,
LEARNING_EXTRACTOR_API_KEY, LEARNING_AUDIT_PASSWORD,
LEARNING_CANDIDATES_PASSWORD, LEARNING_CORPUS_PASSWORD, USER_KNOWLEDGE_PASSWORD and
REVIEWER_TOKEN.
Verify it exists — a missing Secret wedges the pods in
CreateContainerConfigError rather than failing loudly:

  kubectl --namespace {{ .Release.Namespace }} get secret {{ include "data-agent-learning.secretName" . }}

Two keys are worth checking by hand, because their absence is SILENT rather than
fatal: REVIEWER_TOKEN (unset ⇒ every inbox route answers 503 and nothing can be
approved or rejected) and LEARNING_EXTRACTOR_API_KEY (unset ⇒ the consumer starts,
drains the job stream and extracts NOTHING; no candidate ever reaches the inbox).

Rotating a key in that Secret does NOT restart the pods — the chart cannot see its
contents, so there is no checksum to change. Roll them yourself — and EXCLUDE the
redis component, which mounts none of this and whose restart would drop the job
stream on the emptyDir default:

  kubectl --namespace {{ .Release.Namespace }} rollout restart deploy \
    -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component!=redis

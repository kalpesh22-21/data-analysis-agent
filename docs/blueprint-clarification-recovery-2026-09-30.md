# Blueprint slot clarification recovery — 2026-09-30

This change addresses the A/B/C paths reported for trace `132547bb` with local
scripted regressions. The external trace exports were not available in this workspace.

## Root cause and behavior

The blueprint executor previously enumerated up to 500 distinct slot values. A
concrete employee code outside that page could fail membership validation before
the SQL template ran. Concrete scalar bindings now constrain the verification
query before the limit. Successful resolution continues into the template; API
errors and incomplete/malformed probe results return a tool error rather than
pretending that resolution succeeded. Date-only period inputs remain valid when
an equality probe returns a DateTime serialized with a midnight suffix.

A blueprint slot question is generated by deterministic runtime code. It does not
require a post-blueprint LLM call. The old loop honored that ToolPause immediately,
bypassing the askUser refusal gate; the finish-time judge could then reject it,
and the generic withholding path converted the pause into a terminal decline.
There need not have been a missing LLM span: no such model round was required by
this path. No artificial model span is added.

In-loop runtime questions now enter the existing askUser gate. A rejected question
records its refusal, claims the repair allowance, emits the refusal event and
re-rounds with the nudge and existing evidence. Approved or exhausted pauses keep
the blueprint checkpoint metadata. When repair is exhausted, rejection remains
visible in review metadata and the checkpoint remains resumable; question rejection
no longer implies a grounded-answer failure or consumes the checkpoint. A handled
question review is reused at delivery rather than paid for a second time.

## Tracing and regression coverage

`getBlueprint` and `runBlueprint` spans now carry result kind and preview shape.
A runtime pause is explicitly marked `tool.status=paused` and includes its reason
and whether a question exists. Result previews are included only with the existing
redaction-disable setting, capped at 8,000 characters with a truncation flag.
Other runtime tools retain their existing tracing posture.

Tests cover targeted employee/period verification and grouped template execution,
API-error propagation, DateTime period serialization, rejected runtime questions
reaching the next agent round, refusal/exhaustion guardrail spans, resumable spent
allowances, and bounded/redacted blueprint results.
